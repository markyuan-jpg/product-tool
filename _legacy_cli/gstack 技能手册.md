# GStack 技能手册 — OpenCode 版

> 你不用打命令。直接说需求，我自动调对应的技能。

---

## 🧠 规划与思考

| 你说 | 我调什么 | 用来干嘛 |
|------|---------|---------|
| "帮我想个产品点子" / "这个值不值得做" | `/office-hours` | YC 模式拷问：需求是真的吗？用户是谁？最小可行是啥？ |
| "想大一点" / "这个方案格局不够" | `/plan-ceo-review` | 站 CEO 角度：推翻前提、找 10 倍产品、该扩还是该砍 |
| "架构评审一下" / "这个设计靠谱吗" | `/plan-eng-review` | 站技术负责人角度：数据流、边界条件、性能、测试覆盖率 |
| "设计方案看看" / "UI 这块行不行" | `/plan-design-review` | 站设计师角度：布局、颜色、间距、交互一致性 |
| "DX 怎么样" / "开发者体验好不好" | `/plan-devex-review` | 站开发者角度：上手时间、文档、报错信息 |
| "帮我自动跑一遍完整评审" | `/autoplan` | CEO + 设计 + 技术 + DX 一条龙自动评审，最后给结论 |

---

## 🐛 调试与测试

| 你说 | 我调什么 | 用来干嘛 |
|------|---------|---------|
| "这个怎么坏了" / "报错了" | `/investigate` | 系统化排查：调查 → 分析 → 假设 → 修复。不找到根因不改代码 |
| "测一下这个页面" / "帮我 QA" | `/qa` | 浏览器自动测试，发现问题直接修，修完再验证 |
| "只报告 bug，别改代码" | `/qa-only` | 和上面一样但只出报告不动手 |
| "打开浏览器看看" | `/open-gstack-browser` | 打开一个你能看到的浏览器窗口，我操作给你看 |
| "登录这个网站" / "导入 cookie" | `/setup-browser-cookies` | 把你真实浏览器的 cookie 导入到测试浏览器，做登录后的测试 |

## 👀 审查

| 你说 | 我调什么 | 用来干嘛 |
|------|---------|---------|
| "代码 review 一下" / "看看 diff" | `/review` | 预合并检查：SQL 安全、边界漏洞、条件副作用 |
| "外观上看看" / "设计改改" | `/design-review` | 找出视觉问题（间距、字体、颜色），修完截图对比 |
| "安全审计一下" | `/cso` | OWASP TOP 10、密钥扫描、供应链安全、威胁建模 |

## 🚢 发布

| 你说 | 我调什么 | 用来干嘛 |
|------|---------|---------|
| "发版吧" / "提交 PR" | `/ship` | 合入主分支、跑测试、更新版本号/CHANGELOG、提交、建 PR |
| "合并部署一条龙" | `/land-and-deploy` | 合并 → 等 CI → 部署 → 验证线上正常 |
| "设置一下部署" | `/setup-deploy` | 配置部署平台（Vercel/Fly/Render 等） |

## ⚡ 效率工具

| 你说 | 我调什么 | 用来干嘛 |
|------|---------|---------|
| "保存进度" | `/context-save` | 把当前工作进度保存到文件，下次接着干 |
| "我干到哪了" | `/context-restore` | 恢复上次保存的工作进度 |
| "之前有过这个问题吗" | `/learn` | 搜索项目历史经验记录 |
| "周报" / "这周干了啥" | `/retro` | 分析 git 提交记录，按人输出周报 |
| "性能怎么样" / "测一下速度" | `/benchmark` | 页面加载性能检测（Lighthouse、Core Web Vitals） |
| "代码质量评分" | `/health` | 综合评分（类型检查、lint、测试、死代码检测） |

## 🔒 安全模式

| 你说 | 我调什么 | 用来干嘛 |
|------|---------|---------|
| "小心点操作" | `/careful` | 危险操作前（rm -rf、删表、force push）会先警告 |
| "只改这一个目录" | `/freeze` | 锁定修改范围，只允许改指定文件夹 |
| "全锁住" | `/guard` | 危险警告 + 目录锁定，双重保护 |

## 四、审查方法改进

### 关键教训：必须读API路由代码

第一次审查时我只关注了前端UI和架构文档，**没有逐行追踪后端API路由的代码路径**，导致漏掉了4个运行时崩溃。

### 改进后的审查流程

```
1️⃣ 读架构文档（了解全局）
2️⃣ 逐行扫描主要代码文件（前端页面 + 后端路由）
   └─ 重点：追踪每个API端点的变量定义 → 是否有NameError
   └─ 重点：追踪每个try-catch → 是否静默吞掉异常
3️⃣ 按五维清单逐项对照
4️⃣ 交叉验证（两个AI各自的盲区互补）
```

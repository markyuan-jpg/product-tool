## 一、架构总览

### 1.1 前后端分离架构

```
┌─────────────┐     HTTPS      ┌──────────┐     HTTP      ┌──────────────┐
│   Browser    │ ◄───────────► │  Vercel   │ ◄──────────► │  Alibaba VPS  │
│  (Next.js)   │    CDN        │ (landing) │   API calls   │  (backend)    │
└─────────────┘                └──────────┘               │  FastAPI      │
                                                          │  :8000        │
                                                          │  nginx proxy  │
                                                          │  SQLite/PG    │
                                                          └──────────────┘
```

| 层 | 技术栈 | 部署位置 | 入口 |
|---|--------|---------|------|
| 前端 | Next.js 16 + React 19 + Tailwind v4 | Vercel | `landing/app/` |
| 后端 | FastAPI (Python 3.11+) + SQLAlchemy async | 阿里云 VPS 新加坡 | `backend/main.py` |
| 核心引擎 | Python 模块包 | 与后端同机 | `product_tool/src/` |
| 数据库 | SQLite (默认) / PostgreSQL | 与后端同机 | `backend/app.db` / `~/.product_tool/products.db` |

前端通过 `NEXT_PUBLIC_API_URL`（生产环境 `https://api.quoteflow.it.com`）调用后端。
后端启动时将 `product_tool/src/` + `product_tool/` 加入 `sys.path`，直接导入核心模块。

### 1.2 组件树（前端）

```
layout.js (字体/元数据/Sentry/Analytics)
  └─ LocaleProvider (i18n Context)
      └─ ClientLayout → ErrorBoundary
          └─ page.js (各页面路由)
              ├─ Nav (顶部导航)
              ├─ [page content]
              └─ Footer (含 ToS/隐私政策链接)

```

## 四、后端 API 端点全目录

### 4.1 认证系统 (`/api/auth/`)

| 方法 | 路径 | 限速 | 认证 | 参数 | 说明 |
|------|------|:--:|:---:|------|------|
| POST | `/register` | 5/min | 否 | `username`, `email`, `password` (Form) | 注册（邮箱必填 + 唯一性检查） |
| POST | `/login` | 5/min | 否 | `username`, `password` (Form) | 登录，返回 access token |
| POST | `/refresh` | — | Cookie | — | 用 httpOnly refresh cookie 换新 access token |
| PUT | `/change-password` | — | 是 | `old_password`, `new_password` (Form) | 改密 |
| POST | `/forgot-password` | 3/min | 否 | `email` (Form) | 发重置邮件（防枚举：无论邮箱是否存在都返回 ok） |
| POST | `/reset-password` | 5/min | 否 | `token`, `new_password` (Form) | 用 15 分钟有效 token 设新密码 |
| GET | `/user/me` | — | 是 | — | 返回用户信息（id/username/tier/upload_count/email） |
| GET | `/user/usage` | — | 是 | — | 返回上传/产品数量统计 |

**认证实现：**
- 密码：bcrypt 哈希（`passlib[bcrypt] >= 1.7.4`）
- Token：JWT HS256，access token 15 分钟，refresh token 7 天
- 存储：access token 在 `localStorage`，refresh token 为 httpOnly + Secure + SameSite=Strict cookie
- 自动刷新：`lib/auth.js` 的 `apiFetch()` 包装器检测 401 → 自动调 `/api/auth/refresh` → 重试原请求
- 登出：清除 localStorage token（refresh cookie 因 httpOnly 不可读）

## 五、安全架构

### 5.1 安全中间件（后端 `main.py` 添加的响应头）

| Header | Value |
|--------|-------|
| X-Content-Type-Options | `nosniff` |
| X-Frame-Options | `DENY` |
| X-XSS-Protection | `1; mode=block` |
| Referrer-Policy | `strict-origin-when-cross-origin` |
| Strict-Transport-Security | `max-age=63072000; includeSubDomains; preload` |

CORS 白名单：前端域名 + `www.` 子域名。

### 5.2 前端安全头（`landing/next.config.mjs`）

Content-Security-Policy: `default-src 'self'`; `script-src 'unsafe-inline' 'unsafe-eval'`（较宽松）；`img-src` 含 R2 和图床域名；`connect-src` 含 API 域名；`object-src 'none'`；`frame-ancestors 'none'`

### 5.3 限流（`slowapi`）

Per-IP 限流，nginx 感知（通过 `X-Forwarded-For` 获取真实 IP）：

| 端点 | 限制 |
|------|:---:|
| 注册/登录 | 5 次/分钟 |
| 忘记密码 | 3 次/分钟 |
| 重置密码 | 5 次/分钟 |
| 文件解析 | 20 次/分钟 |

### 5.4 输入安全

- 文件上传：扩展名白名单（.xlsx/.xls/.pdf/.docx）+ 大小限制 50MB
- 产品数据：入库前 `html.escape` 清洗所有文本字段（`sanitize.py`）
- 密码策略：bcrypt 哈希 + 最低 6 位
- SQL 注入：SQLAlchemy ORM 参数化查询
- API 签名：Creem webhook 使用 HMAC-SHA256 验证

### 5.5 监控与日志

- **Sentry**：后端 `sentry-sdk` + 前端 `@sentry/browser`（可选，通过 `SENTRY_DSN` 环境变量启用）
- **日志**：标准 Python logging，可选 JSON 结构化输出（`LOG_JSON=1`）
- **前端分析**：Vercel Analytics

## 六、解析器引擎

### 6.1 三解析器协同架构

```
输入文件 (xlsx/pdf/docx)
    │
    ├── 格式检测 (detector.py)
    │
    ├── 通用解析器 (universal_parser.py) ────┐
    │   四层策略: KV→表头→内容驱动→无表头    │
    │                                         │
    ├── 专用解析器 (run.py:parse_file) ──────┤
    │   6 种专用解析器 + 格式特定处理         │
    │                                         │
    └── 双结果评分 (score.py) ◄──────────────┘
         │
         │ 逐产品 7 级信号组合 + 全局一致性加成
         │ 分高者胜
         │
         ├── 图片匹配 (image.py)
         │   按 _row + _sheet 键值匹配
         │
         └── 返回 products JSON
```

### 6.2 Excel 解析器（`universal_parser.py`）— 四层策略

| 策略 | 触发条件 | 适用场景 |
|------|---------|---------|
| **KV 布局** | 参数名含冒号 `Model: S1` | 配置单、参数表 |
| **关键词表头** | 表头含"型号/价格/规格"等 | 标准外贸表格 |
| **内容推断** | 无视表头，分析数据分布 | 无关键词表头的表格 |
| **无表头模式** | header_row ≤ 1 时启用 | 纯数据文件（无表头行） |

### 6.3 PDF 解析器（`pdf_parser.py`）— 四层策略

| 策略 | 说明 |
|------|------|
| KV 规格表 | 检测参数名/值格式的表格（≤2列） |
| 布局检测 | 行优先/列优先表格布局自动识别 |
| 内容推断 | `_classify_pdf_columns` 按数据分布分类列 |
| Docling 回退 | `USE_DOCLING=1` 时启用高级 OCR |

**依赖：** pdfplumber (必需) + PyMuPDF/fitz (必需) + Docling (可选)

### 6.4 DOCX 解析器（`doc_parser.py`）— 三层策略

| 策略 | 说明 |
|------|------|
| 表头关键词 | 扫描含"型号/价格"等关键字的行作为表头 |
| 内容推断 | `_infer_docx_columns` 按数据分布分类列 |
| 段落文本 | 无表格时的自由文本提取 |

**依赖：** python-docx (必需)

### 6.5 关键词体系（`shared_keywords.py`）

共约 120 个关键词，覆盖 25+ 行业：

| 行业 | 覆盖词示例 |
|------|-----------|
| 医疗器械 | 型号、规格、批号、产品名称 |
| 电子/电器 | power、voltage、capacity、频率 |
| 服装/纺织 | 款号、色号、尺码、面料、成分 |
| 机械设备 | 功率、压力、转速、行程 |
| 五金/工具 | 材质、表面处理、硬度、工艺 |
| 家具/家居 | 尺寸、颜色、材质、承重 |
| 化工/原料 | 纯度、含量、浓度 |
| 食品/饮料 | 净含量、保质期 |
| 汽车/配件 | OE no、OEM no、适用车型 |
| 照明/LED | 色温、流明、灯头、显指 |
| 新能源 | 容量、电压、循环寿命 |

**扩展方式：** 在 `universal_parser.py` 的 `COLUMN_SIGNALS` 字典追加即可，无需重启服务。

### 6.6 图片匹配（`image.py`）

所有解析器统一输出 `_row` + `_sheet` 列。通过 `match_images_to_products()` 按行列键值匹配。支持：
- 内置图片匹配（Excel/DOCX 嵌入图片）
- 文件夹匹配（按型号关联本地图片）
- 智能回退（顺序分配，不循环）

### 6.7 评分系统（`score.py`）— 信号组合评分

不再使用简单线性公式，改为信号组合评分：每个产品独立打分后取均值，再加全局一致性加成。

#### 逐产品评分（7 级）

| 条件 | 分值 | 含义 |
|------|:---:|------|
| 真型号 + 有价格 + 有参数(>30字) | +7 | 最强信号 |
| 真型号 + 有价格 | +5 | 强信号 |
| 真型号 + 有参数(>30字) | +4 | 中信号 |
| 真型号（只有型号） | +2 | 可接受 |
| 有价格但无型号无参数 | +1 | 弱信号 |
| 假型号(商品_R/D等) | -3 | 自动生成的假型号 |
| 空型号 + 无价格 | -3 | 噪音行 |
| 型号含冒号或超长(>40字) | -2 | 内容错列 |

**真型号定义：** 2~30 字，含字母+数字，不含冒号。

#### 全局一致性加成

| 条件 | 加分 |
|------|:---:|
| 有 ≥3 个不同的真型号 | +3 |
| 有 ≥3 个产品有价格 | +2 |
| 噪音行(分≤-3)占比 < 20% | +1 |

**最终公式：** `最终分 = (∑ 单行分 + ∑ 一致性加成) ÷ 产品数`

**选择规则：** 专用解析器分 > 通用解析器分 → 选专用。无特殊规则，纯分高者胜。

## 九、关键设计决策

1. **双解析器 + 评分** — 通用解析器与专用解析器并行，信号组合评分选优，准确率提升 ~40%
2. **首页可选认证** — 允许匿名试用（无需注册），降低使用门槛
3. **全 client 组件** — 前端全部 `'use client'`，简化部署但限制 SSR/SEO（工具类 App 可接受）
4. **SQLite 默认** — 零配置适合小规模部署，PostgreSQL 可选扩展
5. **httpOnly cookie refresh** — 防止 XSS token 窃取
6. **nginx 感知限流** — 自定义 `_get_real_ip()` 从 `X-Forwarded-For` 获取真实 IP
7. **邮件三通道回退** — Resend → SMTP → Noop，开发/生产无缝切换
8. **100% REST** — 无 WebSocket，全部请求-响应模式
